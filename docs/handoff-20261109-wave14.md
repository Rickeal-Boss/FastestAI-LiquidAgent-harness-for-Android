### 4.3 长上下文注入与压缩（W12 `F10 ⛔ / F11 ⛔vacuous / F8 ⚠️` 的补跑）

「导入会话（调试）」通道（设置页，JSONL 每行 `role` / `text`，上限 8 MiB / 5000 条）本波**首次真机行使**：
生成 300 条 / 257 kB 会话推入设备 → SAF 选中导入 → 末条 `Segment 0299` 可见 ⇒ 300 条全部落气泡。

| 环节 | 实测 | 四态 |
|---|---|---|
| C05 32K 档直接发请求 | 失败：`context_overflow_prevented: chars=249752 cap=50227`（已被安全熔断） | ⛔ **L3 字符硬闸真实行使**（非缺陷） |
| 自动压缩 | 同段日志仍为 `auto_compact=noop reason=below_trigger`，**未介入前置字符闸** | ⚠️ 触发面差异已另立 `W14-10` |
| 手动压缩 | 确认框（含缓存重建警告）→ `manual_compress dropped=238 kept=64 cache_invalidated=false` | ✅ **W12 的短会话 no-op 变为真 `dropped=N`** |
| C06 压缩后仍在 32K | 失败：`chars=53853 cap=50227`（较压缩前 −78.4%，仍超 7.2%） | ⛔ 如实，不写成通过 |
| C06b 切 128K 档后同一会话 | 18.7s 收敛、`10.4k in / 20 out (0 cached, 0.0%)`、`上下文 10.5K / 123.9K` | ✅ **缓存归零 + 请求收敛双向可见** |
| 压缩后自动压缩分支 | 日志新增 `auto_compact=noop reason=already_compressed` | ✅ 新分支被行使 |

`cap=50227 = 27 904 × 1.8`，与 W6「字符硬预算 / chars-per-token floor 1.8」逐字吻合，
构成本波可复用的**标定对照点**。`cache_invalidated=false` 让 `W11-03` 的二值过度声明在现场再次可见
（本波只登记现象，不改老行）。
⚠️ `W7-03` **不写 CLOSED**：其待证判据还含「分隔卡 / cache_invalidated=true」，本波未取全。
