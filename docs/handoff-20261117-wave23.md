## 一、本波定位与裁决收敛

W23 = **「四外审裁决 + 新节点×多上下文×多功能面真机矩阵 + 上一波收尾契约缺陷次级收口」复合波**：
零 `.kt` 前提下，①裁决四份众审查人分歧（不改方案大体方向 = 用户指令面优先）；②用用户补给节点与密钥
把真机矩阵向功能面纵深铺；③修上一波收尾契约被判的制品可复核 / 脱敏回退 / 面数推送链接等缺陷并回源补录账实。
不是裁决波、不是拆分波、不是 journal 波、不是安全波、不是基础设施波。

**收敛结论（唯一目标以此为准，完整版见验收物 §1.1–§1.4）**：

1. **用户指令面优先**（沿用多波同款裁决）：四份外审的排期主张（停矩阵 / 转拆分 / 决策清点 / 触顶申报）
   整包顺延留痕、不取消不推翻；矩阵存续决策包维持台账原样 `OPEN`，不代做终局裁决。四项用户终局裁决
   （journal 二选一 / ≥3 端点终局 / 占位符口径 / 并行键终端）只留痕、不软化、不关号。
2. **最硬裁决 = 并行键笔误处方第 5 次现役证伪**：其「白名单含笔误键、保存链必拒合法键」前提
   在现役树上不成立（完整键自初始即在，allowlist 强制行为测试已在）；用户未给期望行为裁决 ⇒
   证伪 + 顺延留痕、拒绝修不存在的 bug。「采纳外审处方前先 grep 现役树」铁律本波再 +1。
3. **收尾契约缺陷修复并入本波**（零 `.kt`）：修复上一波自己的收尾契约缺陷是收尾义务的完成，
   不是改变方案大体方向。边界一次钉死：上一波验收物只做最小结构修复；上一波制品 JSON 不重出不覆盖；
   更早各波正文与制品一律不动；台账只新增本波段行 + 被点名老行行内追加注记。
4. **「空转判据」防守**：本波新制品恢复 schema 版本 / cells[] 结构数组 / iterations[] 明细 /
   evidence_ref / attempt_states / truncated_fields，10 条出厂断言每条配必红变异样本并落进制品本体
   （相对上一波段「断言存在但无对象」的退化，本波做到「每条断言有触发对象或注入样本且实跑结果入仓」）。
   脱敏检测器正控自证额外抓出历史 serial 检测器恒不响的既有空转 bug 并修复。
5. **零 `.kt`**：三模块余量与 ViewModel 上限未变，拆分仍是独立波（老号原样 `OPEN`）；
   不调行数上限 / 测试数上限 / 测试期望值。
6. **端点判据前置与口径纠正**：用户标注某 openrouter 模型「视觉双通」，但设备实测其输入模态仅 TEXT，
   ⇒ 以真机事实为准，换设备池唯一含 IMAGE 端点攻多模态；档位 = 应用侧会话预算档位
   （`SettingsRepository.maxContextTokens`），与端点 contextLength 声明无关， corroborated by
   现役 `SwitchGuard` 源码与上一波段切换实据。
7. **不可达格如实**：deepseek 不在设备池、gemma 限流、压缩夹具几何夹紧、无外部 MCP 端点
   ——判据未行使或行使后失败如实四态，环境类不归因应用代码。
