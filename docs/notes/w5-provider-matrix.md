# W5 供应商能力矩阵：长上下文 / 前缀缓存 / 视觉+工具（实测）

> 口径：本文每个数字都来自**本波实际发出的 HTTP 请求**，原始响应落盘可复算。
> 端点：NVIDIA 直连 `integrate.api.nvidia.com`（本文简称 **NV**）、OpenRouter（**OR**）。
> 脚本：`_w5/ctx_ladder.py`（可复跑，`ladder` / `cache` / `vision` / `ceiling` 四个子命令）。
> 原始记录：`_w5/ctx-ladder.json`、`_w5/ctx-cache.json`、`_w5/ctx-vision.json`、
> `_w5/ctx-ceiling.json`（含多轮 `runs[]`）、`_w5/ctx-ceiling-repeat.json`、`_w5/ctx-dots-256k.json`。
> 干草堆生成规则（固定种子可复现）：`_w5/ctx-haystack-spec.json`。
> 凭据：从 `_w5/keys.json`（**不入库**）或环境变量读取，本文不含任何密钥。

三态记号：**✅ 实测通过** / **⛔ 实测失败** / **vacuous 判据失效**（请求成功但判据本身不成立，不能当结论用）。

## 一、结论先行（三条，直接回答交付问题）

1. **NV 直连 nemotron 的真实窗口是 1,000,000 token，且这个数把输出算在内** ——
   不是模型卡常见的 1,048,576。实测 1,000,083 直接被 400 拒，原文
   `This model's maximum context length is 1000000 tokens`。取针上限实测到 **994,998**（✅ 命中）。
   **但"能发进去"≠"能用"**：999,662 token 时只剩 338 token 输出预算，reasoning 把它吃光、
   `content` 空串、`finish_reason=length` —— 这一档必须记 **vacuous**，不能记"失败"，更不能记"通过"。
2. **缓存命中可控的部分只有"前缀逐字节稳定"，其余不可控**。三连发同字节请求：
   `0 → 21,680 → 21,680`（占 `prompt_tokens=23,740` 的 **91.3%**）；把**第一个字符**改掉后命中归零。
   但"是否缓存"由供应商决定：`cohere/north-mini-code:free` 三连发**恒为 0**，
   `dots-3-note-preview:free` 到**第 3 次**才命中 5,120（写入有延迟）。
3. **免费池里唯一能同时承担"视觉 + 工具 + 长上下文"的是 `dots-studio/dots-3-note-preview:free`**。
   本波已把三项**拉到同一时点、同一脚本、同一判据**：视觉 ✅（200×120 图形识别正确）、
   工具 ✅、长上下文 ✅（**254,771 token 取针命中**）。仍有一处缺口：
   它在本波"视觉+工具同轮"的请求里发起了 `tool_call`，`content` 却是空串、没有描述图形 ——
   只能证明"带图时工具仍可用"，**不能**证明"同一轮既读图又调工具"。
   要强证据请用 NV 的 `nvidia/nemotron-3.5-super-vl-120b-a12b`（付费，本轮三者同轮全通）。

## 二、长上下文阶梯（取针，针在 50% 深度）

模型 `nvidia/nemotron-3.5-super-vl-120b-a12b`（NV 直连），`temperature=0`。
判据：`MAGENTA-7731` 出现在 `content` **或** `reasoning_content`（reasoning 模型必须两处都扫）。

| 目标档 | 实测 `prompt_tokens` | 耗时 | 取针 | `cached_tokens` | `finish_reason` | 判定 |
|---|---|---|---|---|---|---|
| ~1k | 816 | 2.21s | ✅ | 0 | stop | ✅ **判据自证档**（先跑这档才允许上探） |
| 8k | 7,768 | 2.16s | ✅ | 0 | stop | ✅ |
| 32k | 32,016 | 12.84s | ✅ | 0 | stop | ✅ |
| 128k | 127,829 | 10.63s | ✅ | 0 | stop | ✅ |
| 256k | 256,282 | 24.39s | ✅ | 0 | stop | ✅ |
| 512k | 512,626 | 54.70s | ✅ | 0 | stop | ✅ |
| ~1M | 999,662 | 120.75s | — | 0 | **length** | **vacuous**（见下） |
| ~995k（`max_tokens=4096`） | 994,998 | 115.12s | ✅ | 0 | stop | ✅ **可用上限** |
| ~1.0M+ | 1,000,083（估算） | 1.76s | — | — | — | ⛔ **400 超窗**（重复观测见 2.4） |
| ~1.04M | 1,040,137（估算） | 3.90s | — | — | — | ⛔ 400 超窗 |
| ~1.06M | 1,060,079（估算） | 2.64s | — | — | — | ⛔ 400 超窗 |

### 2.1 为什么 1M 档是 vacuous 而不是"通过"或"失败"

`prompt_tokens=999,662` + `completion_tokens=338` = **1,000,000**，正好顶死。
也就是说这一档模型**只拿到 338 token 的输出预算**，它把 338 全用来 reasoning
（`reasoning_tokens=338`），还没写出答案就被截断 ⇒ `content` 是空串。

这正是本仓踩过的那个坑的**同构复现**：如果判据只看 `content`、或者只看"HTTP 200"，
就会把这一档记成"1M 不可用"；如果只看 `reasoning_content` 里有没有出现答案，也会记错
（这次 reasoning 里根本没走到答案）。正确做法是记 **vacuous** —— 请求成功，但判据不成立。

放大到 `max_tokens=4096` 后，同样的模型在 994,998 token 上 **✅ 命中**，`content` 直接就是
`MAGENTA-7731`。⇒ 窗口上限是 1M，卡住的从来不是窗口，是**输出预算被 reasoning 吃光**。

### 2.2 延迟

512k→54.7s、995k→115.1s，接近线性。但 32k(12.8s) 比 128k(10.6s) 还慢，说明**单次延迟噪声很大**，
不要用单次测量做 SLA 承诺。

### 2.3 dots 免费模型的 256k 取针（同一套干草堆规则）

目的：把「三合一」结论钉在**同一时点、同一脚本、同一判据**上，不再引用 W4 的二手数据。

| 模型 | 目标档 | 实测 `prompt_tokens` | 耗时 | 取针 | `finish_reason` | 判定 |
|---|---|---|---|---|---|---|
| `dots-studio/dots-3-note-preview:free` | 256k | **254,771** | 10.98s | ✅（`content` = `MAGENTA-7731`） | stop | ✅ 本波实测命中 |

`max_tokens=4096`，`reasoning_tokens=123`，`content` 非空。
⇒ 结论口径：**256k 实测命中（本波）；512k 是模型声明窗口，本波未复测**，不得写成"512k 可用"。

### 2.4 「>1M 被 400 拒」的重复观测

400 这类边界错误可能是网关瞬时行为，所以单独做了重复验证：

| 观测 | 报错时的 token 数 | 结果 | 原文 |
|---|---|---|---|
| 第 1 次（首轮 ceiling） | 1,000,032 | ⛔ 400 | `maximum context length is 1000000 tokens` |
| 第 2 次（复测 ceiling） | 1,000,083 | ⛔ 400 | 同上 |
| 第 3 次（repeat400#1） | 1,005,026 | ⛔ 400 | 同上 |
| 第 4 次（repeat400#2） | 1,005,026 | ⛔ 400 | 同上 |
| 第 5 次（repeat400#3） | 1,005,026 | ⛔ 400 | 同上 |

5 次独立请求、4 个不同长度档位、**错误原文完全一致**，且第 3~5 次 token 数**逐字相同**（1,005,026）
说明 token 计数是确定性的、不是偶发抖动。
⇒ 「1,000,000 是硬上限」由 **≥5 次一致观测**支撑，不是单次观测。

（另：1,040,086 / 1,040,137 / 1,060,029 / 1,060,079 也各返回同一条 400，合计 9 次。）

### 2.5 复现方式

```bash
python _w5/ctx_ladder.py ladder      # 阶梯（1k 起，失败/未命中即停，不盲目上探）
python _w5/ctx_ladder.py ceiling     # 1M 复测 + 找 400 失败点（结果累积进 runs[]）
python _w5/ctx_ladder.py dots256     # dots 免费模型 256k 取针
python _w5/ctx_ladder.py repeat400   # 重复观测 >1M 的 400，排除瞬时行为
```

干草堆：`random.Random(20260918)`，词表固定，每句 12~20 词，取针句插在正中间，末尾追加问题。
完整规则见 `_w5/ctx-haystack-spec.json`。

## 三、前缀缓存

同一档位（NV 侧 `prompt_tokens=23,740`，OR 侧 5k 左右）连发**逐字节相同**的请求 3 次，
再做一次"只改第一个字符"的对照。

### 3.1 NV / `nvidia/nemotron-3.5-super-vl-120b-a12b`

| 次序 | `prompt_tokens` | `cached_tokens` | 命中率 |
|---|---|---|---|
| 第 1 次 | 23,740 | 0 | 0.0% |
| 第 2 次 | 23,740 | 21,680 | **91.3%** |
| 第 3 次 | 23,740 | 21,680 | **91.3%** |
| 对照：改首字节 | 23,740 | **0** | 0.0% |

对照档是**决定性证据**：只动第一个字符，命中立刻归零 ⇒ 命中来自**最长公共前缀**，
不是供应商恒定返回一个非零数。

### 3.2 OR 两个免费模型（同口径）

| 模型 | 第 1 次 | 第 2 次 | 第 3 次 | 改首字节 | `cached_tokens` 字段是否上报 |
|---|---|---|---|---|---|
| `dots-studio/dots-3-note-preview:free` | 0 | 0 | **5,120**（/5,604） | 0 | 上报（字段存在，前两次是 0） |
| `cohere/north-mini-code:free` | 0 | 0 | 0 | 0 | 上报（字段存在，**恒为 0**） |

- `dots` 第 3 次才命中，说明缓存**写入是异步/有延迟**的，客户端不能假设"发第二次就一定命中"。
- `north-mini` 字段存在但恒 0：**"未命中"和"该供应商不缓存"在数据上不可区分**（W3 已记，本波未修）。
- 两个 OR 模型都**上报**该字段，所以不是"没报"，是"真没命中"。

### 3.3 客户端能控 / 不能控

| 能控 | 不能控 |
|---|---|
| 前缀逐字节稳定（工具清单顺序、system 文本、技能拼接顺序、记忆块位置） | 是否开启缓存、缓存粒度（NV 只命中 21,680/23,740，尾部约 2,060 不命中，像按块对齐） |
| 把"变化频率低"的内容放在越靠前的位置 | 写入延迟（dots 第 3 次才命中） |
| 避免每轮都触发压缩（压缩切点后移 = 前缀全失效） | 某些供应商压根不缓存（north-mini 恒 0） |

## 四、视觉 + 工具组合

测试图：`_w5/ctx-vision-input.png`，200×120，白底，**蓝色三角形 + 红色圆形**（PIL 生成，可复跑）。
问题："有几个图形、分别什么颜色"。

| 模型 | 端点 | 纯视觉 | 视觉 + tools 同轮 | 备注 |
|---|---|---|---|---|
| `nvidia/nemotron-3.5-super-vl-120b-a12b` | NV | ✅ "2 shapes: a blue triangle and a red circle"（2.5s） | ✅ 同时给出图形描述 **且** `get_weather{"city":"Beijing"}`，`finish_reason=tool_calls` | **本轮唯一"三件事同轮全通"** |
| `dots-studio/dots-3-note-preview:free` | OR | ✅ "two shapes: blue triangle / red circle"（3.0s） | ✅ 发起了 `get_weather{"city": "Beijing"}`，但 `content` 空、**未描述图形** | 带图时工具可用已证；"同轮既读图又调工具"**未证** |
| `mistralai/mistral-large-4-1t-a52b` | NV | ✅ "2 shapes: one blue triangle and one red circle"（5.8s） | ✅ 描述 + `get_weather{"city":"Beijing"}` | — |
| `cohere/north-mini-code:free` | OR | ⛔ 404 | ⛔ 404 | `No endpoints found that support image input` |

### 4.1 1×1 像素假阴性已排除

上一轮用 1×1 红点测视觉，`mistral` 答 "Black"。本轮换成 200×120 真实图形后，
**同一个 mistral 答对了 "blue triangle + red circle"**。⇒ 上一轮的 "Black" 是
**测试素材太小导致的假阴性**，不是模型视觉能力问题。任何"视觉不可用"的结论都必须用
≥ 百像素级的真实图形复核，1×1 不能作为判据。

## 六、实测 / 推断 分界

**本波实测（可直接引用）**
- NV nemotron 1,000,000 硬上限及 400 原文（**9 次观测、4 个不同长度档位、错误原文完全一致**）；
  994,998 取针通过；999,662 因输出预算不足而 vacuous。
- 阶梯 1k/8k/32k/128k/256k/512k 全部 ✅ 命中。
- dots 免费模型 **254,771 token 取针命中**（同一脚本、同一干草堆、同一判据）。
- 缓存 0→21,680→21,680 与首字节对照归零；dots 第 3 次才命中；north-mini 恒 0。
- 四个模型的视觉单独与视觉+工具同轮结果；1×1 假阴性已被 200×120 推翻。

**推断（未经本波直接测量，勿当结论用）**
- 「1,000,000 是**整个模型族**的窗口」—— 只测了 `nemotron-3.5-super-vl-120b-a12b` 一个模型，
  同族其它模型是否同值未测。
- 「NV 缓存按块对齐、尾部约 2,060 token 不命中」—— 只由单次差值推出，未做块边界扫描。
- 「dots 能跑 512k」—— 本波只测到 254,771，512k 是模型声明值，**未复测**。
- 「north-mini 不缓存」—— 只证明本波三次请求命中 0，不能排除"需要更长前缀才触发"。

## 七、对实现的直接影响

| 决策 | 依据 |
|---|---|
| 端点预算公式必须用 **1,000,000 含输出**，且额外扣掉 reasoning 预算（本波观察到 311~338 token） | §2.1：999,662+338 正好顶死；994,998+4096 才通过 |
| 长上下文判据**必须**同时扫 `content` 与 `reasoning_content`，并把"输出被截断"单列为 vacuous | §2.1：只看 content 会把可用窗口误判成不可用 |
| 缓存优化只做**前缀稳定化**，不做"命中率承诺" | §3.3：客户端只控得住前缀字节 |
| 免费跑分基线用 `dots-3-note-preview:free`，但**不要**用它验证"视觉+工具同轮" | §4：该组合在 dots 上是 vacuous |
| 视觉验证素材下限提高到 ~200×120 真实图形 | §4.1：1×1 会产出假阴性 |
